# GitHub 与求职展示指南

## 这个项目能证明什么

项目的重点不是功能数量，而是两条端到端链路都能解释和验证：

1. 在线链路：Vue 请求如何经过 FastAPI、事务、RAG、Agent 工具和模型，再保存并返回结果；
2. 离线链路：公开数据如何经过许可核验、清洗脱敏、固定切分、QLoRA、评测和 vLLM 发布。

面试时要主动说明公开购物对话只用于学习澄清策略，不是平台政策。确定性政策闸门正是从模型失败
案例中得到的工程改进：概率模型负责语言与工具选择，明确业务边界由代码和数据库负责。

## 三分钟演示顺序

1. 创建会话并发送一个信息不足的商品咨询，展示澄清回复和知识来源；
2. 查询一个当前客户订单，说明工具参数校验、客户隔离和审计日志；
3. 重复提交退款请求，展示幂等键不会创建两条退款；
4. 询问“退款一般几天到账”，展示系统拒绝编造政策且不返回无关引用；
5. 打开 QLoRA 实验报告和 vLLM `/v1/models` 结果，说明训练、推理与应用为何分离。

不要现场重新训练模型。演示训练配置、指标、损失曲线和已知失败即可。

## 高频追问

**为什么使用 Milvus？** 需要持久化向量检索并保留迁移到服务端 Milvus 的路径；本地用 Milvus
Lite 降低学习成本，接口与服务端一致。

**为什么还要 BM25 和 Reranker？** 向量检索擅长语义相似，BM25 保留精确商品词，RRF 融合两路
排序，CrossEncoder 只重排少量候选，在效果和延迟之间折中。

**为什么不用微调模型直接保证安全？** 行为评测已经出现无依据的退货政策回答。微调是统计学习，
不能替代确定性权限、金额、幂等和政策边界。

**为什么只用一张 2080 Ti？** 4-bit QLoRA 在单张 11 GB 显存卡上已能完成实验。双卡没有 NVLink，
在没有单卡瓶颈证据时增加分布式训练只会提高复杂度。

**为什么没有量化部署结果？** 当前 vLLM 使用 FP16 基础模型加运行时 LoRA。项目诚实记录量化未做；
只有能比较显存、延迟、吞吐和行为回归时，量化结果才有意义。

## 发布前检查

- `git status` 中没有 `.env`、数据库、模型权重或个人信息；
- README 的运行命令能在全新环境中理解，CI 全绿；
- 仓库展示一张聊天界面截图、一张训练 loss 图和一段三分钟演示视频；
- 根据希望他人如何使用代码，发布前自行选择并添加项目许可证；
- GitHub 仓库描述中注明 `educational portfolio project`，不声称生产可用。
