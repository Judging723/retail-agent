# 项目范围

## 项目定位

Retail Agent 是一个面向学习和求职展示的电商客服项目，不是生产级电商平台。

项目的首要目标是：代码能够运行，开发者能够解释请求如何经过 API、业务逻辑、数据库和模型服务，再返回给用户。

## 当前 MVP

当前版本只完成一个业务闭环：

```text
创建会话
  → 用户发送消息
  → 读取历史消息
  → 调用 DeepSeek
  → 保存用户消息和助手回复
  → 查询完整会话历史
```

MVP 包含：

- FastAPI 后端
- 客户、会话和消息三张表
- MySQL 数据持久化
- Alembic 数据库迁移
- OpenAI 兼容模型客户端
- DeepSeek 配置
- 多轮对话上下文
- 核心流程测试

## MVP 验收标准

- 可以创建一个新会话
- 同一个客户可以创建多个会话
- 用户发送消息后可以获得模型回复
- 第二轮模型请求包含第一轮对话历史
- 用户消息和助手回复按顺序保存在数据库
- 可以通过 API 查询完整会话历史
- 未配置模型密钥时返回明确错误
- 核心测试和代码检查通过

## 下一阶段

当前 MVP 稳定后，按以下顺序扩展：

1. Vue 3 聊天页面
2. 基础文档切片与向量检索
3. 在回复中展示知识来源
4. 合成订单查询工具
5. 固定离线评测集

每次只增加一个完整、可演示的功能，不提前为尚未实现的功能创建分层、接口或数据结构。

## 暂不实现

- 真实订单、支付或退款操作
- 复杂 Agent 编排框架
- 意图识别和情感分析独立服务
- 权限、审计、灰度发布和多租户
- 高可用集群和跨地域容灾
- 模型注册平台
- 在 Web 服务中执行训练任务

## 训练、微调与量化

这些内容保留为后续独立实验，不与当前聊天后端混在一起：

- 小型意图分类实验
- 客服数据 SFT 构造
- LoRA/QLoRA 微调
- GGUF、AWQ 等量化实验
- vLLM 或 llama.cpp 推理部署

只有当实验产生可复现的模型、数据说明和评测结果后，才接入在线客服应用。

## 数据边界

项目只使用公开许可数据、自编知识文档和合成业务数据。API Key、数据库密码、真实用户资料、模型权重和运行时数据不得提交到 Git。
